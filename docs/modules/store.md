## mdcore/store/ — Vector Store Module

### Purpose
Wraps ChromaDB with a simple interface for mdcore's specific use patterns: chunk upsert, source-level delete, vector search, source-aggregated embeddings for classification, and metadata enumeration.

### Public interface

**`VectorStore(cfg: VectorStoreConfig)`**
- `__init__`: creates `chromadb.PersistentClient` at `cfg.persist_path` (anonymized_telemetry=False), gets or creates collection `cfg.collection_name` with `{"hnsw:space": cfg.distance_metric}`
- `upsert(chunks: list[Document], embeddings: list[list[float]]) -> None`
- `delete(source_file: str) -> None`
- `search(query_embedding: list[float], k: int, filter: Optional[dict]) -> list[Document]`
- `search_in_sources(query_embedding: list[float], source_files: set[str], k: int) -> list[Document]`
- `file_embeddings() -> dict[str, list[float]]`
- `all_metadata() -> list[dict]`

### Collection schema

Collection name: `cfg.collection_name` (default: `"mdcore_vault"`)
Distance metric: `cfg.distance_metric` (default: `"cosine"`)

Per chunk stored:
- **id**: `"{source_file}::chunk::{chunk_index}"` — generated by `_chunk_id()`
- **document**: `chunk.page_content` — raw text
- **embedding**: list[float] from EmbeddingEngine
- **metadata**: dict with primitive values only (non-primitives stripped by IndexWriter._sanitize_metadata before reaching here). Standard fields: source_file, folder_path, filename, heading_breadcrumb, chunk_index, chunk_total, word_count, is_table, is_code, last_indexed

### Search behavior

`search()`:
- Calls `collection.query(query_embeddings=[emb], n_results=min(k, count), include=["documents","metadatas","distances"])`
- Converts ChromaDB cosine distance to similarity: `similarity = 1.0 - dist` (ChromaDB cosine: 0=identical, 1=orthogonal, 2=opposite)
- Adds `_similarity` to metadata of returned Documents
- If collection is empty: returns [] immediately (avoids ChromaDB error on empty n_results)

`search_in_sources()`:
- Uses ChromaDB `$in` filter: `{"source_file": {"$in": list(source_files)}}`
- Delegates to `search()`

### file_embeddings() — used by ClassificationEngine

Returns dict[source_file, mean_embedding]:
- `collection.get(include=["embeddings","metadatas"])` — fetches ALL chunks and embeddings
- Groups embeddings by source_file
- Computes mean embedding per file: pure Python (no numpy), O(n x dim)
- Returns dict for cosine similarity comparison in ClassificationEngine

Performance: For 10,000 chunks at 768-dim embeddings (nomic-embed-text), this fetches ~30MB of data and runs ~7.68M multiply-add operations in Python. Slow for large vaults.

### all_metadata()

`collection.get(include=["metadatas"])` — all chunk metadata without embeddings or documents. Used for keyword prefilter (needs source_file, filename, folder_path) and status display (needs source_file for unique file count).

### Upsert

`collection.upsert(ids=ids, documents=docs, embeddings=embeddings, metadatas=metas)` — ChromaDB upsert overwrites if ID already exists.

### Delete

`collection.get(where={"source_file": sf}, include=[])` -> get IDs -> `collection.delete(ids=ids)`. If no matching IDs: no-op.

### Dimension mismatch

If a new embedding has different dimension than stored embeddings (e.g., switching from nomic-embed-text 768-dim to text-embedding-3-small 1536-dim), ChromaDB raises a dimension mismatch error on upsert. Fix: `mdcore index --force` (clears collection + cache).

### Side effects
- Reads/writes ChromaDB files on disk (persistent client)
- No LLM calls, no network calls (ChromaDB is local)

### Gotchas
- Collection creation with wrong distance_metric: if collection already exists with cosine, changing to l2 in config does NOT change the stored collection's metric. Must `--force` reset to change.
- `_count()` is called on every `search()` to avoid n_results=0 ChromaDB error. Extra DB call per search.
- file_embeddings() loads ALL embeddings — memory and CPU intensive for large vaults. Called once per `mdcore ingest`.
